CHANGELOG - MP Walkthrough & Shift Report
==========================================
History of changes since the original Gemini-generated prototype HTML.

v21 (current) - Team update, bullet format (his 10/19 spec)
------------------------------------------------------------------
- Subject line added: 'Subject: Shift Update - M/D/YYYY (shift
  time)' - date pulled from tonight's blockers, else today.
- ALL-CAPS section headers with blank lines between sections.
- Status-first bullets: 'Ran and hung: 111-113, 211-213, 311-611'.
  Within every status, racks are now collected per side, sorted
  numerically, and re-compressed into runs - so buckets read in
  row order and ranges regroup automatically (the grouping his
  other agent described: same-status racks together, nothing
  dropped).
- Mixed rows with identical patterns now share one bullet:
  '1413, 1513, 1613: 144F and CAT6 ran; OCS staged' - grouped
  even when separated by other rows, ordered by first rack.
- Hall notes render as bullets ('Continued working through cut
  sheet'); SP work notes and Areas of Concern are bulleted lines;
  blockers are per-entry bullets.
- Diff-tested against his exact 10/19 target report: all 21
  expected lines reproduced verbatim (tools/test_report.py).

v20 - FULL data haul + real scanning

------------------------------------------------------------------
- Complete dataset shipped: 28,353 barcodes with A/Z ends +
  192,423 BUF102-relevant preset connection paths (from the full
  Downloads exports). Stored as a compressed side file
  (data/directory.json.gz, 1.5MB) decoded in-browser; the service
  worker precaches it, so it is fully offline after first load.
  Search stays instant: exact/suffix barcode numeric index plus
  substring scan, indexed in time-sliced chunks with progress.
- Real Scan button in the Data Haul Directory: opens the camera,
  decodes cable-flag barcodes, and drops the result straight into
  search. Runs on zxing-wasm 3.1.6 (upgraded from 2.2.4 in BOTH
  apps - fixes a memory leak that matters for all-night scan
  sessions, faster + better decodes, zero API changes).
- Scanner hardened with field techniques from the GitHub research:
  reticle band crop (10x fewer pixels per frame), two-frame voting
  with a label-character gate (misreads never survive), session
  dedupe, and a WebAudio confirmation beep (iOS has no vibration
  API for web apps). Engine shared from vendor/zxing for both apps.

v18 - Guide identity fixes (found by screenshot audit)
------------------------------------------------------------------
- REAL bug: the guide was rendering in LIGHT mode on phones set to
  light - their light-theme CSS rules out-specified our override
  (:root[data-theme="light"] and :root:not([data-theme]) under
  prefers-color-scheme:light, both 2x our specificity), so the
  graphite retheme never showed. Override now mirrors their
  selectors and wins on order; color-scheme forced dark.
- REAL bug: the "< MP Kit" back button never appeared - its
  observer script ran before their #app div existed and crashed.
  Now DOMContentLoaded-guarded; button verified mounting and
  surviving their screen re-renders.
- Identity pass: Scan FAB and active tab now WHITE (our
  primary-action language) instead of their fiber-yellow;
  selection outlines white; redundant hamburger hidden (the More
  tab already does its job); header is back-pill + logo + language.
  Fiber/copper media colors stay semantic.
- Audited via headless-browser screenshots of every page of both
  apps at 390x844 (tools/shoot.py; MSIX-free Playwright + Edge).
  Known leftovers (their code, phase-2 rewrite): walk-mode rack
  drawing zoom shows dead space; help FAB floats over content.

v2 (first GitHub Pages release) - full rewrite of the Gemini prototype
------------------------------------------------------------------
Everything below replaced or rebuilt from the original single HTML:
- Real site layout encoded from the Large Site Cable Installation
  Guide PDF: network rows 1-2; compute rows with pods of 8 rows
  (3-10 / 11-18 / 19-26); CB4 DH2 extends to row 36 (HAC area);
  EOR anchors at spot 11 and 13; middle SPOCS aisle not tracked.
  Halls preloaded: CB5 DH1 (pods 1-3), CB4 DH2 (pods 10-12 + rows
  27-36), CB4 DH4 (pods 10-12). Halls/groups/row counts editable
  in-app.
- Data model: per row, per side (11 = X01-X11, 13 = X13-X22), per
  cable (144F / OCS / CAT6), one status: Not started, Staged, In
  Progress, Ran, Ran & Hung, Remediation. Statuses carry over
  night to night.
- Stamp interactions: status brush + cable scope; tap side = stamp
  side; tap aisle number = stamp both sides; tap a cable pill =
  stamp one cable; range stamp (rows A-B); whole-pod bulk buttons;
  tap-again-to-clear toggle; 60-level undo.
- Live stats per hall (sides by status + per-cable progress).
- Crew chips with auto-counted SP headcount; dated blockers;
  areas of concern; tasks for tomorrow.
- Report compressor producing the site's row shorthand:
  "111-113, 211-213, 301-311, 501-511 & 601-611 - Ran and hung.",
  run compression ("711-1311 & 713-1313"), short/full/plain number
  styles, mixed-side notations. Templates: quick nightly report,
  crew/table style, boss roll-up (per hall, per cable, blockers with
  "(i)", tasks for tomorrow).
- PWA packaging: versioned service worker (cache-first precache +
  activate cleanup), web manifest, 180/192/512 icons, apple-touch-
  icon, viewport-fit=cover + safe-area insets, touch-action
  hardening, first-run install onboarding, storage.persist().
- Data safety: autosave to localStorage; one-tap backup via Web
  Share (files-only payload for the iOS quirk) with clipboard and
  download fallbacks; restore from file picker or pasted JSON;
  in-app report history.
- Fixes vs the Gemini prototype: working iOS clipboard fallback
  chain (Clipboard API -> hidden textarea + execCommand), real
  layout instead of fixed 26 rows, export/backup the prototype never
  had, service worker the prototype never had.
