# guide.html hand-patch layers — what lives where and must survive regeneration

`guide.html` is GENERATED by `tools/integrate_guide.py` from the vendor artifact, but as of v62+ it carries hand-applied layers that the pipeline does NOT know about. **Never re-run integrate_guide.py without porting these layers into it first.** This manifest is the inventory:

| Layer | What it does | Where in guide.html | Source of truth |
|---|---|---|---|
| Graphite theme | Token remap onto kit palette | `<style id="mp-theme">` + sizing overrides after their stylesheet | integrate_guide.py THEME block (stale — hand edits have drifted ahead) |
| Back pill | "‹ MP Kit" button re-asserted into their header by MutationObserver | `addBack()` IIFE + `.mp-back` CSS | hand-applied v18 |
| Embed mode | Kit tiles hide guide chrome (tabs/brand/help FAB) via `body.mp-embed` | CSS block after `.mp-back` + boot IIFE before `addBack` | hand-applied v62 |
| Directory augmentation | 29K-barcode directory results on find renders + wrong-label warnings + **find box on empty find views** | `<script id="mp-dir">` block | tools/guide_directory.js (SOURCE — keep in sync) |
| zxing engine | Shared vendor/zxing swapped for their embedded engine | engine loader patch | integrate_guide.py |
| Training handoff | Dead cloud-gate training page links to hosted course | `needCloud()` / pageTrain patch | hand-applied v50 |

Porting these into integrate_guide.py as named patch layers (with per-layer proofs, the way v28 did for the original five) is the permanent fix; until then this file is the contract.
