1 · The Screen Registry

Strong

index.html — switchTab (1970–1997) · TABS · panel divs (451–595) · nav markup (697–702) · CSS chrome rules (317–327) · renderAll (2058)

Problem. A "screen" is not a module — it's an event scattered across nine sites. Chrome (title, bar, stamp dock, hall tabs, back pill) is toggled by if-branches inside switchTab plus eight CSS rules keyed to body classes. Interface ≈ implementation: zero depth. This exact shallowness shipped three field bugs (wrong dock on Directory, walkthrough bar everywhere, wrong titles). Dead directory branches still sit at 1978–1995 calling dirInit, which no longer exists anywhere.

Solution. One declarative registry: SCREENS = { walk: {title, panel, chrome:{bar,dock,hallTabs,back}, onShow} , … }. switchTab becomes one generic loop over the registry; CSS keys off data-screen on <body>; the nav bar renders from the registry for the current tool.

Benefits. Locality: a screen's whole definition lives in one entry — the wrong-chrome bug class becomes structurally impossible. Leverage: the checked-in nav probe tests the registry, not nine sites. Deletion test: deleting the scatter concentrates the complexity into the map — the signal we want.

2 · Report Engine on a Real Seam

Strong

runsOf (1347) · fmt11/13/Both (1360–1390) · sideOverall (1399) · mixedDesc2 (1660) · formalHallLines2 (1694) · buildReport (1755) · test_report.py

Problem. The formatting core is already ~pure — the only impurities are numStyle() reading the DOM (1343) and buildReport reading global state + effectiveHalls() reading #reportScope (1619). Yet the diff-test needs Edge + Playwright + a dev server to exercise string logic. The seam exists in fact but not in code: no adapter, so tests pay the browser tax.

Solution. Extract the core to report-engine.js taking (state, opts); index.html keeps a 3-line adapter wiring DOM globals in; tools/test_report.py gets a second adapter running the same file in Node — the 21-line diff test becomes instant and CI-able.

Benefits. One engine, two adapters (app + Node test) = a real seam by the two-adapter rule. Every future report-format change gets a sub-second gate instead of a 40-second browser run.

3 · Check In the Probe Suite

Strong

lost probes: nav-per-screen · 16px font gate · copy round-trip · chrome probe — all run as throwaway python -c

Problem. The gates that caught the real bugs (v23–v27) were written as one-off scripts and evaporated. The 16px iOS-zoom rule survives as a fix, not a check. Tribal tests are no tests.

Solution. tools/probes.py: the nav-chrome probe (registry-driven after #1), font gate, copy round-trip, title-per-screen — wired into gate.py next to verify + report-diff.

Benefits. Locality: every "does the screen wear the right clothes" question has one permanent home. The three nav bugs this week would each have been a red gate before shipping.

4 · Guide Pipeline Layer Proofs

Worth exploring

tools/integrate_guide.py — 5 patch layers, only final boolean checks · absolute SRC/DST paths ×4 scripts

Problem. The generator is a good deep module (one interface: run script → guide.html) but its patches aren't individually provable. Upstream changes break loudly (style-count assert, ZXing regex) or silently — THEME's foreign selectors (.top .brand .tabs) can stop matching with all checks green. That is the light-mode bug's genus.

Solution. Per-layer output diffing + a selector-presence check ("THEME layer requires .top/.brand/.tabs in the output") + relative paths via __file__. Benefits: silent-break class dies; pipeline stays one-command.

5 · State Module: Version + One Shape

Worth exploring

defaultState (781) · loadState (842) · snapshotCore (861) · doUndo (872) · applyRestore (1940)

Problem. version:1 is written but never read — no migration seam, so any future shape change breaks old phones silently. The state shape is hand-enumerated in three places. Factory defaults ship real personnel names and pre-stamped rows — fixture welded to blank state.

Solution. Read + migrate on load; one shape constant; split DEMO fixture from blank state. Benefits: future format changes become safe; restore/undo share one definition.

🏁 Top recommendation

#1 Screen Registry — strongest evidence (three shipped bugs from one shallowness), smallest blast radius, and it directly feeds #3 (the nav probe tests the registry). #2 is the best testability win and is independent. #1 → #3 together retire the entire wrong-chrome bug class permanently.
