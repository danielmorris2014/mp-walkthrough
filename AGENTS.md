# MP Kit — agent notes

Offline-first iPhone PWA for Midpoint/ServicePoint night-shift data hauls.
Single-file vanilla JS/CSS, zero dependencies, no build step. Push to `main`
ships it live via GitHub Pages (CDN lag up to ~2 min).

## Multi-agent protocol (MANDATORY — two agents work on this repo)

These rules prevent stale-code overwrites. Follow them every time, no exceptions.

### Before touching anything

1. **`git pull origin main`** — always. Never edit from a stale checkout.
2. **`git log --oneline -10`** — read what the other agent shipped since your last commit.
3. **`git diff HEAD~N --stat`** (where N = the other agent's recent commits) — see which files changed. If they touched files you're about to edit, read their diff first.
4. **Check the live version**: `curl -s https://danielmorris2014.github.io/mp-walkthrough/index.html | grep APP_VERSION` — confirm the live version matches what you expect.

### While working

5. **Work fast, commit fast** — don't sit on uncommitted changes; the other agent may push while you're editing.
6. **Before every commit**: `git pull --rebase origin main` — if there are new remote commits, rebase onto them, resolve conflicts, THEN commit.
7. **After conflict resolution**: verify no `<<<<<<<` / `=======` / `>>>>>>>` markers remain in ANY file (`grep -r "<<<<<<" . --exclude-dir=.git`).
8. **Commit message must say WHAT and WHY** — the other agent reads these to understand your changes.

### Before pushing

9. **Run the full gate**: `python tools/gate.py` — if it fails, fix before pushing.
10. **Push immediately after commit** — don't batch pushes; each push should be one logical change.

### Version numbering

11. **Bump `APP_VERSION` in index.html AND `CACHE_VERSION` in sw.js together** — they must match, and verify.py enforces the pair.
11b. **`git add sw.js` in the SAME commit as index.html** — the bump means nothing if it rides the working tree (v42-v46 all shipped the v41 sw.js; only CI's version-pair check caught it, because the local gate reads the dirty tree and passes). `git status` before every commit: a dirty sw.js you meant to include is a red flag.
12. **If both agents pushed since your last pull, bump past the highest version** (e.g., if remote is v35.3, your push is v35.4+ even if you expected v35).
13. **Never reuse a version number** — the service worker uses this to trigger phone updates.

### File ownership awareness

14. **`index.html`** — shared by both agents. Highest conflict risk. Read the other agent's diff to this file carefully.
15. **`guide.html`** — generated by `tools/integrate_guide.py`. If you need to change it, edit the build script and regenerate. The other agent may have also regenerated it.
16. **`report-engine.js`** — shared report formatter. Changes here affect the diff test.
17. **`sync-engine.js`** — sync module. Changes here affect multi-phone sync.
18. **`tools/`** — validation and pipeline scripts. Safe to add new files; be careful modifying existing ones.

### When things break

19. **If the app is broken on Daniel's phone**: check the live version first, then check recent commits from both agents, then reproduce locally with `tools/shoot.py`.
20. **If there's a merge conflict**: keep the version that preserves Daniel's explicitly requested behavior (his feedback > design principles). When in doubt, keep both changes if possible, or ask Daniel.

## Map

- `index.html` — the whole Kit: Home launcher, Walkthrough & Report, Data Haul Directory (search + barcode scan).
- `guide.html` — Cable Field Guide (foreign app). Regenerate with `tools/integrate_guide.py` after editing that script — never hand-edit guide.html.
- `data/directory.json.gz` — 28k barcodes + 192k presets, decoded in-browser (DecompressionStream, iOS 16.4+). Rebuild with `tools/build_directory_full.py` from the Downloads exports.
- `sw.js` — precache list. `vendor/` — Leaflet + shared zxing-wasm engine (both apps use it).
- `retro/` — session retros. `tools/` — all pipelines and gates.

## Invariants — break one, break the field app

- Every edit to `index.html` or `guide.html` bumps `APP_VERSION` and `CACHE_VERSION` **together**; stale service-worker caches otherwise serve old code for days.
- Focusable inputs are `font-size >= 16px` everywhere, both apps. iOS zooms the whole page on focusing anything smaller (the "double scroll" bug).
- No network at runtime, no CDNs, no dependencies. Everything works in the data halls with zero signal.
- Report-engine changes must pass `tools/test_report.py` (Playwright diff vs Daniel's real report format).
- UI changes get a rendered screenshot (`tools/shoot.py`, headless Edge) before shipping — static checks miss rendering bugs (v17 shipped a theme that never rendered).
- **Fixed chrome owns the bottom of the screen.** Never hand-write a `padding-bottom` / `bottom` pixel constant for body, toasts, or overlays — `applyChromeHeight()` measures `.bottom-stack` and exposes `--chrome-h`; derive from it (`calc(var(--chrome-h) + ...)`). Probe 5 in `tools/probes.py` fails the gate if body padding doesn't clear the measured chrome on any screen (the v35.5 "blockers tab sizes weird" bug: 57px nav, 24px padding, 33px of content hidden).
- Any new bottom-fixed element goes **inside `.bottom-stack`** so it's measured automatically — never a sibling `position: fixed; bottom: 0` element.
- The guide's cloud features (login/pairing/time clock) are dead by design — Claude's servers. Degrade silently, don't restore.

## Checks

- `python tools/gate.py` — one command, self-contained: static verify + report diff test (`--shots` adds every screenshot). Run it before shipping.
- `tools/verify.py` — esprima syntax + onclick-handler/id cross-checks. Runs in CI (`.github/workflows/ci.yml`, with a credential scan) and pre-commit.
- Hooks: `git config core.hooksPath scripts/hooks` (once per clone).
- Local Playwright gates need `pip install playwright` and Edge (`channel='msedge'`).

## Deploy

Push to `main`. Phone update: open once with signal, close fully, reopen, tap **Update now** on the yellow banner.
